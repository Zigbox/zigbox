Diagnostic code

ZBX-E0906

no trusted signed provenance covers what was to run

Kind
error
Blame
user
Exit code
1 (125 in zbx run)

What it means

A policy file asked for require_provenance, and the build result this run would start from has no signed provenance that satisfies it. Nothing was started: no container, no run record.

"zbx build" writes a SLSA provenance record for every result it makes, hit or miss. The record is only a claim until a key signs it ("zbx sign <result>" signs the stored record, byte for byte). It satisfies the rule when the signature verifies, its key is one the policy lists, and it is about this tree and bound to the result that is to run.

The cause says which of five things is wrong. Nothing has recorded a build of this result (it was built by an older zbx, or not built here): build it again. A record is stored, or a provenance signature is present, but no key the policy lists signed it: sign it, or add the signer's key to the policy. A listed key signed provenance for another result: run that one. A pulled or pushed image is judged by the result its record derives from its tree, settings and labels: a signed provenance of that result covers it, and the causes above apply to it. If its record does not keep the labels (it was pulled by an older zbx, or they did not fit), no result can be derived: pull the image again. What is to run may also be no build result (a base image of a build, which never derives one, or a bare tree): only a result built by zbx carries provenance, so a policy that requires it cannot be met by one. A directory given as --rootfs has no tree to sign and is refused as ZBX-E0905.
