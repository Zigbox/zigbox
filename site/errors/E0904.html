Diagnostic code

ZBX-E0904

a policy file cannot be read or is not a policy

Kind
error
Blame
user
Exit code
1 (125 in zbx run)

What it means

A policy file says which keys you trust and what a run must have. zbx reads /etc/zbx/policy.zon and ~/.config/zbx/policy.zon (or $XDG_CONFIG_HOME/zbx/ policy.zon) before every run, exec and build step, and every file that exists must be a policy: a file that is not is refused and nothing runs, because a policy that cannot be read must not be taken for "no rules".

A policy is a restricted ZON file: .{ .version = 1, .keys = .{ .{ .name = "release", .public = "zbx-ed25519:..." } }, .require_signature = true, .verify = "cached", } Only .version is required. Fields come in any order, once each. There are at most 16 keys, none listed twice, and the file is at most 16 KiB. .require_provenance is not supported by this zbx yet and is refused.

The system file, /etc/zbx/policy.zon, must be owned by root and not writable by group or others: a file anyone else could rewrite is no rule, so it is refused too. As root, "chown root:root /etc/zbx/policy.zon" and "chmod 644 /etc/zbx/policy.zon" put it right.

The cause gives the line and column and what was expected there. Correct the file, or remove it (the system file: ask the administrator). "zbx policy check" reads the policy files and runs nothing.
