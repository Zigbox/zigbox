# Zigbox 0.5.2

0.5.2 adds the four runtime requests of Zigcube's C4 milestone ([brief](../briefs/zb-c4.md),
[decision](../decisions/2026-11-14-zigcube-c4-requests.md)). Same scope as
[0.5.1](0.5.1.md): Debian and Fedora only. Everything is in `v0.5.1..main`.

## What is in

- **ZB-5, `container_socket`.** A host program asks for a TCP listener made inside a running
  `--net none` container's network namespace and gets the socket back over SCM_RIGHTS. A
  single-threaded forked helper joins the user then net namespace, so no thread changes
  namespace. Refused with E0610 for a container with no network of its own (`--net host`), E0402
  for an unknown name, E0220 for a stopped container.
- **ZB-6, `--hosts-file PATH`** (`Spec.hosts_file`): a read-only bind of a file you own at
  `/etc/hosts` in place of the generated one. Only with `--net none`; a path that is missing, not
  absolute or not a regular file is refused with E0612. An in-place rewrite of the file is seen
  inside; a rename-over is not (the bind is of the inode).
- **ZB-7:** a simulation test and a demo step that `zbx exec` joins the container's net
  namespace. Writing it found a bug: `exec` into a `--net host` container panicked on a missing
  net-namespace handle (fixed in c030f8a, it now runs in the host network).
- **ZB-8:** a simulation test and a demo step that a ZB-5 socket survives adoption by a
  restarted agent.

New codes: **E0610**, **E0611**, **E0612**. `demo-c4` passed in an Ubuntu 24.04 VM with KVM
([run](https://github.com/Zigbox/zigbox/actions/runs/43607006674), cuts in
[docs/demos/c4.md](../demos/c4.md)).

## Upgrading

The run record format is unchanged (version 10), so 0.5.2 reads every store and record 0.5.1
wrote, and the reverse.

## Known issues

- **`zbx start` of a stopped container forgets `--hosts-file`.** The run record was not bumped,
  so a restarted container gets the generated `/etc/hosts`. Run it again with the flag.
- `--hosts-file` is for `--net none` only, and sees a rename-over of the host file only after a
  restart.
- No IPv6, UDP or Unix sockets for `container_socket`; one guest kernel was exercised.
- The 0.5.1 known issues are unchanged.
