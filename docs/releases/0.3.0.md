# Zigbox 0.3.0

Hermetic, reproducible builds (M7), and the store and pull APIs Zigcube C2 builds on.

## Builds (M7)

- `zbx build` runs a step DAG from a build file. Each step's key covers exactly the inputs it reads, so a rebuild reruns only what changed, and a second clean machine produces the same image digest.
- A step has no network unless the build file grants it; without the grant it fails with `ZBX-E0805`, which says how to grant it.
- `--verbose` streams step output line by line. `--output json` gives a versioned build result. `zbx run` takes a build result's full digest.
- The `zigbox.build` library export lets a program drive builds without the CLI.
- Demonstrated by `demo-m7` in two clean Ubuntu 24.04 VMs with KVM ([PR #38](https://github.com/Zigbox/zigbox/pull/38)). The demo on the Mac was cut.

## For Zigcube (Z1–Z7)

- Store and pull APIs in the `zigbox` module ([PR #39](https://github.com/Zigbox/zigbox/pull/39)): verified chunk reads (`read_chunk`, `Fs.read_at`), a checked tree put and `has`, a bounded object walk, and bytes and outcome per blob in the `pull` result.
- Peer image import ([PR #41](https://github.com/Zigbox/zigbox/pull/41)). An image tree received from a peer is accepted only against the manifest digest the caller expects (`expected_manifest`). A mismatch is refused before anything is written, and every chunk is checked against its BLAKE3 digest.
- `hostfwd` port forwards in the VM harness, so guests can serve each other in tests ([PR #40](https://github.com/Zigbox/zigbox/pull/40)).

## Security note: peer transport

Zigbox trusts peer data only by digest. Zigcube carries chunks between nodes over an **interim** Noise-style handshake that authenticates nodes against the cluster CA. This handshake is a stopgap, documented as such: the target is mutual TLS. Zigcube's server-side mTLS will be open-sourced before EC2 self-hosting (Zigcube C5). Until then, run peer traffic only on networks you trust.

## Upgrading

A store written by 0.2.x is read as is. `demo-m7` runs an upgrade test from 0.2.0.
