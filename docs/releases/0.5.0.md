# Zigbox 0.5.0

0.5.0 adds the listener handoff (M8b), packages signed by CI, and a user guide. Everything is in `v0.4.0..main`. There is no new milestone: M8 shipped in [0.4.0](0.4.0.md).

## Listener handoff (M8b)

- `zbx run --net none --listen 127.0.0.1:PORT --listen-send FD` makes a loopback listener inside the container's network namespace and sends it once, over the Unix socket `FD` (SCM_RIGHTS), to a host program, which accepts the connections ([PR #89](https://github.com/Zigbox/zigbox/pull/89)). The brief is [docs/briefs/M8b-listen.md](../briefs/M8b-listen.md); the demo and its deviations are in [docs/demos/m8b.md](../demos/m8b.md).
- New codes E0606 to E0609 (`site/errors/`). A bad `--listen-send` is refused before anything starts; a send that fails afterwards (E0609) stops the container.
- Run records are version 10 only when a listener is set; a plain run still writes version 9.
- `-d` with `--listen`, and `--listen` on macOS, are refused under E0606.

## Packages signed by CI

- The release workflow (`.github/workflows/release.yml`, `.github/release-sign.sh`) signs the deb and rpm repository trees on a `v*` tag with the release subkey, in the tag-only `release` environment, and attaches `zigbox-repos.tar.gz` to the release ([PR #99](https://github.com/Zigbox/zigbox/pull/99)). The primary key stays offline. `docs/releases/packaging.md` is rewritten for the subkey setup and its yearly renewal.
- 0.4.0 had no package archive ([decision](../decisions/2026-11-11-no-package-archive-for-0.4.0.md)); this release's archive is the first one zigbox.org serves.
- Not done: the release workflow does not tell the site repository; the site picks the asset up on its six-hourly deploy ([decision](../decisions/2026-11-11-release-workflow-does-not-dispatch-the-site.md)).

## Mac build

0.5.0 ships a Mac build, signed and notarized by the owner after the tag: the owner runs `zig build mac-release -Dnotarize` on their own Mac and uploads the zip to the release; the Homebrew tap is bumped after that. CI does not sign the Mac build in 0.5.0 ([decision](../decisions/2026-11-11-mac-release-signed-by-owner-for-0.5.0.md)). The tap is still at 0.3.1 (0.4.0 had no Mac build). Before the tag, the `mac` workflow must be green and the real-Mac M8 checks of slice 9 in `docs/demos/m8.md` must have run; neither is claimed here.

## Fixes and CI

- Demos match listener checks on the local address's port only, so a peer address ending in the port no longer fools `demo-m6` ([PR #100](https://github.com/Zigbox/zigbox/pull/100)).
- CI installs apt packages through `.github/actions/install-apt` without depending on the Azure mirror ([PR #102](https://github.com/Zigbox/zigbox/pull/102)).

## Documentation

- A user guide under [docs/guide/](../guide/index.md): try on Mac, on Linux (apt and dnf), in Claude Code, a tour of the core loop, and known limits ([PR #105](https://github.com/Zigbox/zigbox/pull/105), link fix in [#106](https://github.com/Zigbox/zigbox/pull/106)). Its examples were run with 0.4.0; spots marked verify-before-0.5.1 in the guide are not yet re-run.
- Briefs and decisions only, no code: the Docker parity scope, the M9 Dockerfile import brief and the M10 GPU brief ([#103](https://github.com/Zigbox/zigbox/pull/103), [#104](https://github.com/Zigbox/zigbox/pull/104)).

## Upgrading

Nothing in this release changes a store or record format for runs without `--listen`. A run record written with `--listen` is version 10, which 0.4.0 reads as `Newer` and refuses; keep that in mind before going back to 0.4.0.
