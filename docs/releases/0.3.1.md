# Zigbox 0.3.1

A patch release: Zigcube's peer server can serve every one-chunk object, and two import and history fixes found by the fuzzers. Everything is in `v0.3.0..main`.

## For Zigcube (Z9)

- `read_chunk` called outside the store's namespace no longer refuses a one-chunk object owned by a container id other than the caller's own ([PR #53](https://github.com/Zigbox/zigbox/pull/53)). Such objects, `etc/shadow` (0:42) among them, read as `Damaged` because the object id commits to container ids and `lstat` outside the namespace gives host ids. The store now has `Store.owners`: `.inside` (the default, unchanged for every `zbx` command) or `.outside`, the store's id map seen from the host. An owner the map does not reach still reads as `Damaged`, never a guess. `zigbox.Facts` is exported.
- **Action for Zigcube:** the peer server needs this line in its adapter, after it opens the store. Without it the reader behaves as in 0.3.0. See `docs/decisions/2026-11-04-z9-chunk-read-outside.md`.

  ```zig
  const outside = zigbox.store.namespace.outside_owners(host, &facts);
  store.owners = .{ .outside = outside.map }; // and log W0201 if `outside.fallback`
  ```

- Known limit, not fixed: a peer server that is not root cannot open objects whose mode denies the host user (such as mode 0000 files), and reads them as `Unreadable`. Root agents are unaffected. The decision document says what a fix needs.

## Fixes

- Import: a failed extended-attribute read fails the import with `E0414` naming the path, instead of silently dropping the attribute. Only `AccessDenied`, `Unsupported` and `NoData` still skip an attribute, with `W0411` ([PR #45](https://github.com/Zigbox/zigbox/pull/45)).
- A damaged or hand-edited exec history file with an empty exit field is refused as malformed instead of failing an assertion ([PR #47](https://github.com/Zigbox/zigbox/pull/47)). Affects 0.2.0 and 0.3.0.

## Project

- CI: Zig and toolchain caches, one fuzz job, and affected demos only on pull requests ([PR #44](https://github.com/Zigbox/zigbox/pull/44)).
- Docs: release gates, the 0.3.0 retro, the SPEC resync, and the M8 brief (Linux packages, trust).

## Upgrading

A store written by 0.3.0 is read as is.
