# 0.5.3 ships M6d built but not demonstrated; its live demo moves to 0.6.0

*Decided 2026-11-17, by the owner.*

The owner, verbatim: "Yes, we can ship 0.5.3 as is and defer demo to 0.6.0".

## What this means

0.5.3 ships M6d (private pull from Artifact Registry and gcr.io,
[scope](2026-11-16-0.5.3-scope.md), [brief](../briefs/M6d-gar.md)) with all three slices built and
reviewed ([#175](https://github.com/Zigbox/zigbox/pull/175),
[#179](https://github.com/Zigbox/zigbox/pull/179), [#181](https://github.com/Zigbox/zigbox/pull/181)),
and **not demonstrated**:

- **Not demonstrated.** `demo-m6d` has never run against Google. It needs the owner's Google
  project (two Artifact Registry repositories, a `gcr.io` repository, a workload identity pool and
  provider) and the repository variables `ZBX_GAR_PROVIDER`, `ZBX_GAR_SERVICE_ACCOUNT`,
  `ZBX_GAR_REGISTRY` and `ZBX_GCR_REGISTRY`, as listed in [docs/demos/m6d.md](../demos/m6d.md).
  Neither exists yet. No pull from a real Artifact Registry or gcr.io repository with credentials
  has been made by zbx, on CI or by hand, and the GCE metadata-server check by hand has not been
  run either.
- **What is shown.** Unit tests, the simulation in `src/google/` (the credential sources, the
  token exchanges, the realm and every refusal), the `parse_google` fuzzer, the goldens and error
  pages for E0560 to E0572, and the demos that pull public images (whose output and `zbx.lock` do
  not change).
- **Still open.** Artifact Registry's answer to valid credentials for a repository that does not
  exist is unverified ([decision](2026-11-16-m6d-missing-repo-unverified.md)).

The live M6d demo moves to 0.6.0. Until then the README and the site say "built, not
demonstrated (live demo deferred to 0.6.0)", and the release notes say the same.

## CI

`demo-m6d` stays in CI. Without the repository variables its gate (`.github/actions/m6d-setup`)
writes `demo-m6d: NOT RUN (...)` as a warning and the job stays green
([decision](2026-11-17-m6d-slice3-oidc-in-the-vm.md)). A `NOT RUN` is never reported as a passed
demo. Once the owner's setup exists, the job runs the demo for real; M6d is marked demonstrated
only when that run is green.
