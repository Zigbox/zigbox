# 0.5.2 ships S2 (lazy start) dormant

*Decided 2026-11-16, by the owner.*

S2 slices 1 to 4 ([brief](../briefs/S2-lazy-start.md)) merged to `main` before 0.5.2 was cut,
and S2 ships as 0.6.0 under its own gate. The owner chose to keep S2's code in 0.5.2 but make it
unreachable, so that a 0.5.2 user meets none of it. The S2 code is present in the binary but
unreachable.

What changed, on `claude/release-0.5.2` only:

- **Push and export write layer writer 1.** `zbx push`, `zbx push --dry-run` and
  `zbx store export` pack with `push_run.release_writer_version` (1) instead of
  `constants.layer_writer_version`, which stays 2. A pushed or exported layer has no lazy index
  and no `org.zigbox.lazy-index` annotation, and the same tree gets the same layer and manifest
  digests as under 0.5.1. Every reader still reads writer 2. The test "export and push --dry-run
  write layer writer 1, with no lazy index (0.5.2)" (`src/store_commands_tests.zig`) checks this,
  and the E0555 golden is back to its 0.5.1 text: the blob digest in it is 0.5.1's again.
- **`zbx run --lazy` is refused at parse time** with E0004, "lazy start arrives in 0.6.0", with the
  fix "leave out --lazy". No new code was registered. The refusal sits behind a build option,
  `lazy_start` in `build_options`, which is false in every build but one: demo-s2-lazy's `zbx`
  (`lazy_start_options` in `build.zig`). The shipped binary and the unit tests refuse `--lazy`.
  E1208 is still raised behind the option, so its golden is now built directly, as E1207's is.
- **demo-s2-lazy keeps running in CI**, on its own `zbx` with lazy start on. A build option was
  smaller and safer than a `ci.yml` rule: the release pull request merges into `main`, whose push
  runs every demo, so a rule keyed on the release branch would have left demo-s2-lazy failing on
  `main` after the merge. Every other demo builds and tests the binary that ships.

Reason: the owner wants 0.5.2 to carry C4 and M9 without changing what a 0.5.1 user's pushes
produce. Writer 2 changes every pushed digest, and `--lazy` is not finished (the chunk resolver
is not wired into the server, docs/demos/s2.md); both belong in the release that ships S2.

`main`: the release pull request merges into `main`, and `release.yml` tags the merged release
commit there, so this change lands on `main` with the release. S2's 0.6.0 work on `main`,
starting with [#169](https://github.com/Zigbox/zigbox/pull/169) (slice 5) or a follow-up to it,
undoes it and turns writer 2 and `--lazy` back on: `release_writer_version` goes back to
`constants.layer_writer_version`, the `lazy_start` option and `lazy_not_yet` in `src/cli.zig`
are removed, and E1208's golden goes back to a `run --lazy` command line.
