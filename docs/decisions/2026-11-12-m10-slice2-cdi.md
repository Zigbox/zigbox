# M10 slice 2 (CDI): decisions and handoff

Status: **in progress**. Branch `claude/m10-slice2`. Built and unit-tested: the pure parser and
resolver (`src/runtime/cdi.zig`, `cdi_tests.zig`), CDI names in the device list
(`devices.zig`), the exec supplementary-groups carry-over. Not built: everything below under
"Not done". No gate (`zig build check`) has run, no VM check, no PR.

## Decisions

- **Device text.** `Device.path` stays the text as asked. `/dev/...` is a host path; anything
  else with a `=` is a CDI qualified name `vendor/class=name`. `devices.asked_problem` decides
  by text; `Problem.bad_name` is new. `look`, `resolve` and `plan_input` skip names.
- **Record text bound.** The run record has room for 896 bytes of device text (found by trying:
  `records.zig`'s comptime budget fails at 1024). `constants.run_devices_text_bytes_max = 896`,
  `ListProblem.too_long` refuses a longer list. A UUID-style NVIDIA name is 63 bytes at most
  (`cdi_device_name_bytes_max`), so 14 of them fit. **User-visible; the supervisor should
  confirm it.** Raising `record_bytes_max` instead is the alternative.
- **Unsupported edits** are recorded when the spec is parsed and refused (E0227, naming the
  edit) only when a requested device has them. Edits: hook other than the ldcache hook,
  `intelRdt`, `additionalGids`, a mount type other than `bind`, a node whose `hostPath` differs
  from `path` or whose type is not `c`, two mounts at one container path from different hosts.
- **Hook rule.** `hookName` is `createContainer`, the path's basename is `nvidia-cdi-hook` or
  `nvidia-ctk`, and an argument is `update-ldcache`. Each `--folder X` becomes an ldcache
  directory.
- **`=all`** uses a device literally named `all` if the spec has one, else every device of that
  spec. Common edits apply once per spec; nodes dedupe by path, mounts by container path, env
  later-wins, ldcache dirs dedupe.
- **A file that fails to parse** is a `FileProblem`, not fatal when the device is found in
  another file. `.yaml` and `.yml` give `Problem.yaml` without parsing.
- **Bounds** (all named in `constants.zig`, `cdi_*`): name 128, kind 48, device name 63, spec
  256 KiB, 16 files, 64 dir entries, per spec 64 devices / 128 nodes / 256 mounts / 128 env /
  32 ldcache dirs, strings 96 KiB, one string 1024, depth 12, scanner scratch 32 KiB, path 256,
  per run 32 nodes / 128 mounts / 16 env / 16 dirs / 48 KiB strings, names listed in E0230: 16.
  `plan_steps_max` 224 to 232 (internal; must stay at most 255, the failure record names a step
  in a byte).

## Not done (in this order)

1. **Discovery** (`cdi_discover.zig`, or inside `run.zig`): `/etc/cdi`, `/var/run/cdi`,
   `$XDG_CONFIG_HOME/cdi` (`Host.environment`, `Host.list_directory`, sorted, at most
   `cdi_spec_files_max` files, `Host.read_file` into a buffer of max+1 to see "too big"). Feed
   `Resolver.add_file` / `refuse_file` / `finish`. Then `Host.stat` each mount source (missing:
   E0226 stale; set `mount_is_dir`) and `devices.look_path` each node (not openable: E0225).
2. **`Spec.cdi: ?*const cdi.Resolved`** for Zigcube's agent; null means discover through the
   Host (so `zbx start` re-resolves after a reboot). `Handle.cdi` holds the Resolved; the
   256 KiB file buffer and `Parsed` live on the stack of the resolve function. Keep new state
   out of .bss.
3. **Failure mapping.** Unresolved name and any `FileProblem`: E0226 for the first problem
   (YAML fix text: `nvidia-ctk cdi generate --format=json`). Otherwise E0230 with up to 16
   known names. `Refusal.unsupported` is E0227. `Refusal.too_big` is E0226. Diagnose in a new
   `cdi_diagnose.zig` next to `devices_diagnose.zig`.
4. **Plan steps** (`plan.zig`): `bind_cdi_nodes` (after the user devices), `stage_cdi_mounts`
   (before pivot_root: bind into `rootfs/dev/.zbx-cdi-N`, remount read-only),
   `move_cdi_mounts` (after pivot: make target file or dir, `MS_MOVE`, remove stage),
   `run_ldconfig` (`Host.run_helper`, `/sbin/ldconfig` or `/usr/sbin/ldconfig`, before caps and
   user drop). Loop steps encode the failing item as `errno | (index << 8)` in
   `errno_override`; diagnose decodes it. Fix the existing assert
   `80 + state_volumes_max*8 + mounts_max*6 + 2*run_devices_max <= plan_steps_max` in
   constants.zig for the new steps and check the sim table sizes. Stage names end in one digit
   (`mounts_max` is 8): CDI stages need their own prefix `.zbx-cdi-`, up to
   `cdi_run_mounts_max` (128) so the digit rule does not apply to them; `devices.is_reserved`
   already refuses a user path starting with '.'.
5. **`plan.keep_groups`** from "asked devices > 0" (names count); `child.zig:162` still uses
   `plan.device_count > 0` and must switch to it. A run whose only device is a CDI name has
   `device_count == 0` until it is resolved, so this is a real bug if missed.
6. **Env merge** (CDI env into the container environment: see `run_env.zig`, `build_plan`) and
   **W0208**: no ldconfig in the image, so the ldcache dirs go on `LD_LIBRARY_PATH`. A

## Traps

- `std.json.Scanner`'s FixedBufferAllocator on `Parsed.scratch` never frees per token, so many
  escaped strings end as `too_deep`; that is by design and tested.
- `records.zig:445` has a comptime budget of the record. Any new record text must fit it.
- `zig build test` takes over 120 s: run it in the background with output to a file.
- A test file must be imported from a test root (`main.zig`).
