# Zigbox 0.5.2 holds Zigcube's four C4 requests only

*Decided 2026-11-14, by the owner (recorded by the slice, `claude/zb-c4-requests`).*

The owner set the next release as Zigbox 0.5.2. It contains the four runtime features Zigcube's
C4 milestone (the service mesh) needs, named ZB-5 to ZB-8 so they do not clash with Zigcube's
earlier ZB-1 and ZB-2 (done in 0.5.1, #144), and nothing else:

- **ZB-5** `container_socket`: a socket made in a running container's network namespace.
- **ZB-6** `hosts_file` / `--hosts-file`: a caller-owned file bind-mounted read-only at
  `/etc/hosts`.
- **ZB-7** a test that `zbx exec` joins the container's network namespace.
- **ZB-8** a test that a ZB-5 socket survives the caller's adoption by a restarted agent.

Work that is not one of these waits for 0.5.3 or later. The contract Zigcube codes against is
[2026-11-14-zigcube-c4-requests.md](2026-11-14-zigcube-c4-requests.md); the brief is
[../briefs/zb-c4.md](../briefs/zb-c4.md). The release process of AGENTS.md ("Releases") applies
unchanged: sim-clean, two independent Opus reviews, a retro.
