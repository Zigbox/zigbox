# M0 demo: `zbx doctor` on a real Ubuntu 24.04 host

There are two ways to run this demo: by hand on your own machine (for presenting), or
automatically in a throwaway VM (`zig build demo-m0`, which is also what CI runs). Both run the
same four steps.

## What a failure looks like

Every failure follows [DIAGNOSTICS.md](../../DIAGNOSTICS.md). `zbx doctor` keeps one line per
check on **stdout**; a failing check ends its line with its code, and its diagnostic goes to
**stderr**, one block per failing check, in check order:

```
$ zbx doctor
ok   kernel  6.8.0-45-generic x86_64 (minimum 5.15)
FAIL userns  AppArmor restricts unprivileged user namespaces  [ZBX-E0101]
ok   cgroup  cgroup v2, user@1000.service delegated to uid 1000: cpuset cpu io memory pids
FAIL overlay  a user namespace can be created, but writing its id map was refused  [ZBX-E0104]
ok   subid  alice (uid 1000): subuid 65536 ids, subgid 65536 ids; newuidmap: setuid root, ...
ok   seccomp  seccomp is supported (current mode: disabled for this process)
error[ZBX-E0101]: can't create a user namespace
  cause  this host restricts unprivileged user namespaces through AppArmor
         (kernel.apparmor_restrict_unprivileged_userns = 1)
  fix    allow them system-wide:   sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
         keep it after a reboot:   echo 'kernel.apparmor_restrict_unprivileged_userns = 0' | ...
  more   zbx explain E0101 · rerun with --verbose for the full cause chain
  docs   https://zigbox.github.io/zigbox/errors/E0101.html

error[ZBX-E0104]: can't mount overlayfs in a user namespace
  cause  the kernel created the namespace and then refused the write to its
         uid_map, gid_map or setgroups file; an LSM policy can forbid that, and
         only the user's own id may be mapped without newuidmap
  fix    look for the policy that denies it:   sudo dmesg | grep -iE 'apparmor|seccomp|...'
         if the userns check failed too, fix it first (ZBX-E0101)
  more   zbx explain E0104 · rerun with --verbose for the full cause chain
  docs   https://zigbox.github.io/zigbox/errors/E0104.html
```

(This is what the VM run in step 2 prints, shortened where a line is very long.)

(The two streams are interleaved here as a terminal shows them.) The codes, `E0101` to `E0106`
(one per check), are explained offline by `zbx explain E0101` and on the generated pages in
`site/errors/`. `-v` adds the `while`, the cause chain and the context; `--output json` writes
each block to stderr as one JSON object per line and leaves the stdout report as it is.

| Exit code | Meaning |
| --- | --- |
| 0 | every check is `ok` (a `warn` does not change it) |
| 1 | a usage error: the user's (`zbx frobnicate`, a bad option) |
| 2 | the host or environment: any doctor FAIL, or an output stream that cannot be written |
| 70 | a bug in zbx (`bug[ZBX-B0001]`) |

The exit code comes from the blame of the diagnostic, in one place (`src/diag/codes.zig`).

## By hand, on your own Ubuntu 24.04 machine

You need Ubuntu 24.04 (or another systemd distribution with cgroup v2), a normal user account
you are logged in as through a desktop or SSH session, `sudo`, and Zig 0.17.0. Steps 1 and 2
change no settings permanently except the prerequisites below, which `zbx doctor` itself names
if they are missing.

**Prerequisites (once).** Skip any that `zbx doctor` already reports as `ok`.

```sh
sudo apt install uidmap
# Only if your user has no line in /etc/subuid and /etc/subgid:
sudo usermod --add-subuids 100000-165535 --add-subgids 100000-165535 "$(id -un)"
# Ubuntu 24.04 blocks user namespaces for unconfined programs by default:
echo 'kernel.apparmor_restrict_unprivileged_userns = 0' \
  | sudo tee /etc/sysctl.d/60-zigbox-userns.conf
sudo sysctl --system
```

**Build.**

```sh
zig build release
cp zig-out/release/x86_64-linux/zbx .    # or aarch64-linux
```

**Step 1: the host is ready.** Every line starts with `ok` and names what was found.

```sh
./zbx doctor; echo "exit $?"            # six ok lines, exit 0
```

**Step 2: a broken host is diagnosed.** Turn user namespaces off, see the code, the cause and
the runnable fix, turn them back on.

```sh
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=1
./zbx doctor; echo "exit $?"            # FAIL userns ... [ZBX-E0101]; the block above on stderr; exit 2
./zbx doctor 2>/dev/null                # only the stdout report
./zbx doctor -v 2>&1 >/dev/null         # only the stderr blocks, with the cause chain
./zbx doctor --output json 2>&1 >/dev/null   # one JSON object per failing check
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
./zbx doctor; echo "exit $?"            # six ok lines again
```

**Step 3: one static binary.**

```sh
file zbx                                # ELF 64-bit ... statically linked, stripped
ls -l zbx                               # well under 2 MB
```

**Step 4: a mistyped command is the user's error.**

```sh
./zbx frobnicate; echo "exit $?"        # error[ZBX-E0001]: unknown command, on stderr; exit 1
./zbx explain E0001                     # the long explanation, offline
```

## Automatically, in a VM

`zig build demo-m0` boots a pinned Ubuntu 24.04 cloud image in QEMU, provisions it, and runs the
four steps of the milestone's demo script against the release binary. It is the only thing
that shows M0 works; unit tests, simulations and fuzzers never stand in for it.

### What it does

1. **Fresh VM.** As the unprivileged user `demo` (uid 1000), `zbx doctor` prints six `ok` lines
   (kernel, userns, cgroup, overlay, subid, seccomp), writes nothing to stderr, and exits 0.
2. **User namespaces disabled.** As root in the guest, `sysctl -w` turns on
   `kernel.apparmor_restrict_unprivileged_userns`, then sets `user.max_user_namespaces=0`. Each
   time `zbx doctor` must:
   - end the `userns` line with `[ZBX-E0101]` (and carry no fix text on stdout);
   - write an `error[ZBX-E0101]: can't create a user namespace` block to stderr, with a `cause`
     line and a `fix` that names the sysctl that was just changed
     (`kernel.apparmor_restrict_unprivileged_userns`, then `user.max_user_namespaces`);
   - write exactly one block per `FAIL` line (the `overlay` check fails too, as `ZBX-E0104`,
     because it needs a user namespace);
   - exit 2, the environment's code (DIAGNOSTICS.md).

   The sysctls are then restored and doctor must be all `ok` again, with an empty stderr.
3. **Static binary.** `file zbx` in the guest must say "statically linked". The harness also
   reads both release binaries (x86_64 and aarch64) and checks, in Zig, that each is a 64-bit
   ELF for the right machine with no `PT_INTERP` and no `DT_NEEDED`, and is under 2 MiB.
4. **A usage error.** `zbx frobnicate` must print `error[ZBX-E0001]: unknown command` on
   stderr, nothing on stdout, and exit 1 (the user's code).

Any mismatch fails the run with the step, the expectation and the guest's own output above it.

**Keeping stdout and stderr apart.** The guest's serial console merges the two streams, so the
harness cannot tell them apart by order. Every `zbx` command is typed as
`<command> 2>/tmp/zbx-stderr; ZBX_S=$?; echo ZBX-STDERR""-FOLLOWS; cat /tmp/zbx-stderr; exit
$ZBX_S`: stderr goes to a file in the guest, is printed after a marker line once the program
has ended, and the program's own exit status is kept. `src/testing/vm/checks.zig` cuts the
console text at the marker (and refuses output with no marker, or two). The log shows the two
parts under `--- stdout` and `--- stderr`. The marker is written in two quoted halves in the
typed command, so an echo of the command line can never be mistaken for it.

### Running it

```
zig build demo-m0                 # KVM: needs a usable /dev/kvm
zig build demo-m0 -Daccel=tcg     # software emulation: no KVM needed, about 10 times slower
```

Without KVM and without `-Daccel=tcg` it stops at once with one line saying how to opt in.
Timeouts are scaled by 8 under TCG. It needs `qemu-system-x86_64` and `qemu-img` (QEMU is the
only external program the project uses for testing); everything else (the HTTP seed server, the
image download and its SHA-256 check, the ELF checks) is Zig.

Prerequisites and decisions, all in `src/testing/vm/`:

- **Image.** `image.zon` pins a dated Ubuntu 24.04 release by URL and SHA-256. It is downloaded
  into `.zig-cache/zbx-vm/` on first use and verified on every run; the guest disk is a qcow2
  overlay on it that is deleted afterwards, so the base is never modified.
- **Provisioning** is cloud-init NoCloud, served over HTTP by the harness (QEMU's SMBIOS
  `ds=nocloud;s=http://10.0.2.2:<port>/`), with no ISO tools: the user `demo` with subuid and
  subgid `100000:65536`; `uidmap` installed; lingering enabled for `demo`, so the systemd user
  manager (`user@1000.service`) exists however commands arrive; a passwordless root shell on the
  serial console, which is how the harness runs commands.
- **A host prerequisite, detected by doctor.** Ubuntu 24.04 ships
  `kernel.apparmor_restrict_unprivileged_userns=1`, which makes user namespaces useless to
  unconfined users, and `zbx doctor` correctly reports that on a stock install. The VM
  persists `0` in `/etc/sysctl.d/60-zigbox-userns.conf`. Step 2 turns it back on on purpose.
- **cgroup delegation needs no drop-in.** Stock Ubuntu 24.04 delegates `cpu memory pids` to
  `user@1000.service`, which is what doctor checks, so the VM does not add a `Delegate=` file.
  (`-Ddelegate-dropin=true` provisions one, to try the other case.)
- **Serial console, not SSH.** Commands go over the guest's serial console, so the harness
  needs no `ssh` client and no key. The VM is throwaway and offers no other way in.

### CI

`.github/workflows/ci.yml` has jobs `build` (both targets, size gate), `tidy`, `test`,
`errors-site` (`zig build errors-site-check`: the generated `site/errors` pages match the
registry), `fuzz` (one job per fuzzer, random seed printed) and `demo-m0` (installs QEMU, enables KVM with the
udev rule GitHub documents, caches the base image keyed on `image.zon`, runs
`zig build demo-m0 -Daccel=kvm`). The job's log is the harness's own output, guest console
included.

### Developer notes

- The development container has no `/dev/kvm`. QEMU was installed there with
  `apt-get update && apt-get install -y --no-install-recommends qemu-system-x86 qemu-utils`
  (the container is ephemeral; repeat this after a restart).
- A full run under TCG takes about 8 to 16 minutes (boot and cloud-init dominate). To iterate on the
  harness or on doctor, keep the provisioned disk with `-Dkeep-overlay=true` once, then use
  `-Dreuse-overlay=true` to boot it again (about 4 minutes, no provisioning). Both are
  development aids; the real demo always provisions a fresh VM.
- Everything the guest prints is echoed with a `  vm| ` prefix, and the seed server's
  requests with `  http| `.

### Cut from M0

Decided in `docs/briefs/M0-diagnostics.md`; each cut keeps the demo and the diagnostics standard
intact for everything M0 does.

- **Bundles and `zbx bundle`**, including the CI redaction check. M0 has no state directory and
  no secrets to redact. A panic prints the `bug[ZBX-B0001]` block without a "saved" line, and
  the stack trace goes nowhere a user sees it. The live spec (rev 43) moves bundles to M1's
  acceptance criteria.
- **`zbx doctor --fix`.** The standard's example uses it, but the fix M0 shows is the `sysctl`
  command itself, printed as a runnable line.
- **Segmentation faults** are not turned into a diagnostic: std's SIGSEGV handler would print a
  stack trace, so it is switched off (`std_options.enable_segfault_handler = false`) and the
  process dies by the signal.
- **Exit code 3** (an external service failed) is defined but unused until the registry and
  store arrive (M3 and M4).
