namespace, the locks on every exit path, `zbx state ls`, `state rm` with a trash, `state restore`,

### Layout

```
$XDG_DATA_HOME/zbx/state/            (or ~/.local/share/zbx/state)
  <name>/data/                       the volume's files, bound into the container
  <name>/state.zon                   created, last used, last container, last path, :ro
  <name>/lock                        flock target
  .trash/<name>@<seconds>/           a volume `state rm` moved, whole
```

`<name>/`, the record and the lock are the user's own; `data/` is made by the container's root
inside the container's user namespace (the plan step `make_state_data`, after the id maps are
written and before the user is changed), so it is owned by root in the container and by the user
on the host, and what the container `chown`s inside it is owned through the map (postgres's 999 is
100998 on a host whose range starts at 100000).

### How a run mounts a volume

1. `--state` is parsed as it is read: a bad name is `E0705`, a bad path or list `E0005`. A target
   is absolute, every part a name (no empty, `.` or `..` part, no `:`), at most 256 bytes, not `/`,
   not under `/proc`, `/sys` or `/dev`, not one of the generated `/etc` files, and holds no `:`, space or control byte. One run names a
   volume once, and no target is at or below another's.
2. In `start`, after everything that can fail without the volumes (the name, the checks, the
   scope, the image), each volume's directory is made if new, its lock taken, and its record
   read (a damaged or newer one is `E0712`) and written with this container, its path and the
   time. The volumes are taken last so that every later way out of `start` lets them go.
3. In the child, before the new root is entered: `data/` made, a hidden directory
   `/dev/.zbx-state-<n>` made on the container's fresh `/dev`, the volume bound there, and made
   read-only for `:ro`. After the new root is entered: the target is made with its parents and
   the volume moved onto it (`MS_MOVE`), and the hidden directory removed. The target is so read
   as the container reads it: a symlink in the image resolves inside the container, never on the
   host. A failed step is `E0713`.
4. The run record (version 6) lists the volumes as one string of `--state` values separated by
   spaces (a target holds no space), the way slice 1 keeps the `-e` names: two strings in a row
   would read to the bundle's redactor as a secret's name and value.
5. `wait` lets the locks go once the container is reaped.

### The lock: what holds it, and why

- **The holder is the process that calls `start` and `wait`**: `zbx run` in the foreground, the
  supervisor of a detached run (`run -d` forks the supervisor before `start`, so the caller of
  `run -d` never holds it), or Zigcube's agent's supervisor. The lock lives in the library's
  `Handle`, so a library caller gets the same rule.
- **flock on an `O_CLOEXEC` descriptor.** The container's child inherits it through `clone3` and
  closes it at `execve`; the keeper closes every descriptor it does not need; pasta's `execve`
  closes it. Only the holder keeps the open file description, so its death frees the lock.
- **Every exit path:** a clean exit, an exit code, `zbx stop` (the supervisor's `wait` returns),
  `--timeout`, a killed container: `wait` releases after the reap. A start that fails releases
  before it returns (an `errdefer` from the moment the volumes are taken). SIGKILL of `zbx` or of
  a supervisor: the kernel closes its descriptors, and the container's PID 1 dies with its parent
  (`PR_SET_PDEATHSIG`), so a volume never has a writer its lock does not know of.
- **A lock file left by a crash** is only a file: flock is not persistent. Nothing cleans it up
  and nothing needs to. The text an exclusive holder writes (`<pid> <container>`, cut to 64 bytes)
  is read only when the lock is found held exclusive, and a refusal names the holder by the
  running run record whose supervisor is that pid, else by the text.
- **A run waits half a second** (`state_lock_wait_ms`) for a busy lock before it refuses, so a
  `zbx state rm` holding it for a moment is not mistaken for a writer; `state rm` itself does not
  wait. A second writer is `E0706`, exit 125, naming the container; a reader beside a writer, and
  a writer beside readers, the same.

### The state commands

- `zbx state ls [--output json]` (`zbx.state.ls/1`): each volume's name, size (`disk_bytes`, the
  blocks on the disk, and `bytes`, the files' sizes, each inode once), `files`, created, last
  used (the last time a run took it), last container and path, whether a running container uses
  it and which (from the run records), and the trash with each entry's expiry. The size is
  counted in the store's namespace child; a count that stops (an unreadable file, a tree past 64
  levels, past the entry or hard-link bounds) is `W0702` and the size is `null`, never a guess.
- `zbx state rm NAME` (`zbx.state.rm/1`) takes the lock exclusive without waiting (busy: `E0706`),
  and in the namespace child renames the volume to `.trash/<name>@<seconds>`, then empties every
  trash entry past `store_trash_seconds` (7 days), as gc does with its own trash.
- `zbx state restore NAME` (`zbx.state.restore/1`) takes the newest trash entry of the name:
  none is `E0709`, an expired one `E0710` (it is not brought back; the next `rm` empties it), a
  volume made again under the name `E0708` naming both. The rename runs in the namespace child.
- `zbx store gc` works inside the store's directory only; a test plans and confirms a gc past every
  expiry beside a state directory and checks every path under `state/` is unchanged.

### Decisions the brief left open

- **The size is the disk's.** `ls` shows `disk_bytes` in text; JSON has both.
- **"Last used" is when a run last took the volume**, written at the start: a run killed with
  SIGKILL cannot write at its end, and the start is the one time every run passes.
- **The trash holds the whole volume directory**, record and lock included, under
  `<name>@<seconds>`; two removals of one name are two entries, and `restore` takes the newest.
- **A `:ro` first use makes the volume**, empty, as a read-write one does.
- **The mount targets' rules** are slice 3's in the brief ("Other mounts"); slice 2 needed them
  for `--state` and implements them in `volume.target_problem`, which slice 3 can share.

### Cuts and known limits

- The run fuzzer does not generate `--state` runs; the exit paths are covered by
  `volume_tests.zig` one by one, and the VM part.
- `restore` renames over the name after checking it is free; a run making the name in the same
  instant loses to `rename(2)`'s rules (it fails on a non-empty directory). Not seen, not tested.
- Expired trash that cannot be removed stays for the next `rm`, silently.
- In the simulator the container model and the file tree are separate; a test that checks both
  puts the volume's directory in each.

### Failure modes

| What | How it shows | Recovery |
| --- | --- | --- |
| a volume in use by another run | `E0706` naming it, exit 125 (1 for `state rm`) | `zbx stop <name>`, or `:ro` |
| a bad name, a bad path | `E0705`, `E0005` | fix the flag |
| no `HOME`/`XDG_DATA_HOME`, or a state directory that cannot be made | `E0711` naming the path | set one, free space |
| a damaged or newer `state.zon` | `E0712` | move it aside; the data is not in it |
| a mount step refused, or a missing path in a `--read-only` root | `E0713` | `zbx doctor`; a path the image has |
| `rm` of a name that is not there | `E0707` | `zbx state ls` |
| `restore` with nothing in the trash, after the expiry, over a new volume | `E0709`, `E0710`, `E0708` | `zbx state ls` |
| a size that cannot be counted | `W0702`, size `null` | count it by hand in the user's namespace |
| zbx or its supervisor killed | the lock is free; the container died with it | run again |

### What was checked

- Unit and simulation tests (`zig build test`): the rules of names, values, targets and lists at
  and past each bound; `state.zon` round-trips, version 1's fixed text reads, every bound `render`
  asserts is refused by `parse`; run record version 6 round-trips, and version 4 (M5) and
  version 5 (slice 1) text, captured from those writers, reads;
  the lock's modes, a crash freeing it, the bounded wait; the size walk; a run making the volume as
  the namespace's root, its mounts in the container's table, the record and the run record; the
  plan's order of steps; a second writer refused naming the holder, readers shared; the lock let go
  after a clean exit, an exit code, SIGKILL of the container, a failed start, `zbx stop`,
  `--timeout`, a dead zbx, a detached supervisor; refusals of bad values before anything is made;
  `state ls`/`rm`/`restore` in text and JSON against the schemas, every refusal; gc leaving
  `state/` alone. Goldens and pages for every new code.
- Fuzzers at 10,000 iterations, seed 1: `state` (new: damages `state.zon` and re-renders what
  parses; names, values and trash names from random bytes) and `record` (now with volumes, and
  re-rendering what a damaged record parses to). Mutation: removing `parse`'s `last_used` bound
  or its `last_used >= created` check makes the `state` fuzzer fail.
- The VM: see "The VM check" below.

### The VM check (demo-m5's STATE part, until demo-m6)

postgres gets its password with `-e POSTGRES_PASSWORD=demo` (slice 1); `psql` reads `PGPASSWORD`.

| Step | Command | Passes if |
| --- | --- | --- |
| 1 | `zn run -d --name pg --state pgdata:/var/lib/postgresql/data --publish 5432:5432 -e POSTGRES_PASSWORD=demo postgres:16`; `psql -h 127.0.0.1` creates a table and a row | exit 0; psql exit 0 |
| 2 | `zn run --state pgdata:/data alpine -- true`; `state ls --output json` | `ZBX-E0706` naming `pg`, exit 125; in use by `pg`, last container `pg` |
| 3 | `kill -KILL` of pg's PID 1; `flock -n` of the lock; the same `run -d`; `psql -tAc 'select v from t'` | lock free; the row is there |
| 4 | `state ls` (text and JSON) | pgdata, at least 1 MiB, last container `pg` |
| 5 | `zn stop pg`; `run --state pgdata:/d:ro postgres:16 -- stat -c '%u %g %a' /d`; `touch` in a `:ro` run | lock free; `999 999 700`; the touch fails |
| 6 | a clean exit, `--timeout 2000`, SIGKILL of a foreground zbx, SIGKILL of a detached supervisor | the lock free after each |
| 7 | `state rm pgdata`, `state ls`, `state restore pgdata`, `state ls --output json` | exit 0; pgdata back, last container `st4` |
