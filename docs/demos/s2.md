# S2 demo notes

## Slice 4 (the lazy FUSE server)

The VM check is `zig build demo-s2-lazy` (`src/testing/vm/main_s2_lazy.zig`). Slice 6's `demo-s2`
replaces it.

### Scope cuts

- **`zbx run --lazy -d` is refused with E1208.** A detached run would need the server to outlive
  the `zbx` process that started it, which slice 4 does not build. The refusal says "not yet
  supported", and the VM check asserts the code and the exit status 125.
- **Passing a descriptor of the mount out of the container is not scripted.** See
  `docs/decisions/2026-11-14-s2-lazy-teardown.md` for what an outside holder sees. The VM check
  covers the two exits that are scripted: the container killed in the middle of a read (`zbx`
  returns) and `zbx` killed with SIGKILL (nothing is left in `/proc/mounts` or in fusectl). The
  unit test of `Server` over a socket pair covers the stop flag, which bounds teardown no matter
  who holds the mount.

### What the eager-vs-lazy comparison leaves out, and why

The guest lists every entry of `/` (`find / -xdev`, without the mount points) in an eager run and
in a lazy run of the same image, and requires the two listings to be identical. For each entry
the listing has the type and mode, uid, gid, and for a file its size and checksum, for a link its
target, and for a directory its link count. It leaves out:

- **A file's link count.** An eager tree is made of hard links into the store, so a file's
  `st_nlink` there counts the store's links too. The lazy run checks the count on its own instead:
  the image's hard-link pair (`/big`, `/big.link`) shares one inode and counts 2.
- **A directory's size.** It is whatever the file system reports (4096 on ext4, something else
  over FUSE). It carries none of the image's data.
- **Times.** A store tree keeps none: both the server and the materialized tree report one fixed
  time (`store_mtime_seconds`), so the listing gains nothing from them.

**Device nodes, FIFOs, sockets and whiteouts cannot occur in a store tree.** A tree entry is a
file, a directory or a symlink (`store/tree.zig`, `Kind`). Import refuses or leaves out devices,
FIFOs and sockets, and it turns a whiteout into the removal it stands for (`store/import.zig`). So
the server never has one to serve, and the listing needs no case for them.

### Image additions

Before the import, the guest adds the following to the Alpine minirootfs:

- `/big`: 3 MiB of random data, so reads cross the 1 MiB store chunks. The guest reads 3000
  bytes at offset 1048000, which straddles the first boundary, and then the whole file.
- `/big.link`: a hard link to `/big`.
- `/cold`: a 64 KiB file with the user xattr `user.zbx.demo=lazy`. The guest checks the value,
  checks that the file lists exactly that one name, and checks that no `overlay` xattr shows on
  `/`.
- `/s2-list.sh`: the listing script.
