# M8 demo: trust

This document grows slice by slice. Until the `demo-m8` job is green in CI, M8 is built, not
demonstrated. There is no `demo-m8` yet: it comes with slice 2.

## Slice 1: keys, with passphrase encryption

`zbx key new <name>`, `key list` and `key show <name>` make and describe Ed25519 signing keys
in `$XDG_CONFIG_HOME/zbx/keys` (default `~/.config/zbx/keys`, mode 0700; a key file is 0600).
A new key's secret is sealed under a passphrase with argon2id and XChaCha20-Poly1305, or kept in
the clear with `--no-passphrase`. `list` and `show` read only the `.pub` files and never need a
passphrase. What ran so far: unit and simulation tests (`zig build test`), the `key` fuzzer, and a
smoke run of the real binary on a Linux host that is not the test VM. The VM has not run it.

### argon2id measurement

`zbx key new` with a passphrase file, t=3, m=64 MiB, p=1, a `ReleaseSafe` build, five runs in
the Claude Code cloud container (4 vCPUs, Xeon at 2.3 GHz; not the test VM):
107, 108, 105, 121 and 121 ms. The whole command, not only the hash. The defaults stay at the
brief's. The VM measurement is **not yet run**; it is recorded here by the demo in slice 2.

### Known limits (accepted)

- **A forgotten passphrase is a lost key.** There is no recovery and no reset.
- **The `.pub` file's second line (the encryption word) is advisory.** `list` and `show` believe
  it; `.key` is the truth, and a later slice that opens the key reads the `.key` file.
- **argon2id's memory is taken from the OS** (`page_allocator`) for one call, because the
  command line has no allocator. The only allocation of the program, bounded by the parameter
  limits that `parse` enforces (at most 128 MiB).
- **No key deletion, rotation or export** yet: slice 1 only makes and shows keys.

## Slice 10: pack and export (lane U)

Built: `zbx store export --oci <source> <dir>` (an OCI image layout, `zbx.export/1` with
`--output json`), `zbx push --dry-run <source>` (packs and prints the manifest digest; the upload
is slice 11), the `zigbox.push` library surface, gc of pack records, the pack fuzzer, and a
`src/push/` rule in `.github/ci-changes.sh`.

Run: `zig build test`, `zig build tidy`, `zig build fuzz -- pack`, `zig build fuzz -- gc`,
`zig build check` (see the report). VM check `demo-m8` (`vm/m8-export` on CI): one tree imported
and exported as two users in the guest; layouts byte-identical, every blob hashes to its file
name, the layer reads back with the guest's `tar` and `gzip`. It is the slice's check, not the M8
demo.

Not run: no OCI tool (skopeo, crane, umoci) exists in the build container. `tar -tvzf` of the
golden layer was read here (GNU tar 1.35): the entries, modes, symlink and empty directory match
the golden.

Cuts and deviations (accepted for now): depth-first per-directory sorted entry order;
`source.resolve` accepts a bare tree digest; E0417 reused for export write failures; mode and
uid fields clamped, the real value in pax; gc deletes pack records instead of trashing them and
does not print their count; `zbx push --dry-run --output json` prints the same line as text;
`ci-changes.sh` has no table test.
