# M8 demo: trust

This document grows slice by slice. Until the `demo-m8` job is green in CI, M8 is built, not
demonstrated.

## Slice 6: packages

`zig build packages` writes the `zigbox` deb and rpm for x86_64 and aarch64 and the apt and dnf
trees around them; `zig build packages-check` reads the tree back. The owner signs in two rounds
([docs/releases/packaging.md](../releases/packaging.md)); `-Dtest-key` signs with a fixed test
key instead, for CI. The writers in `src/package/` know nothing about `zbx`; `src/package_release.zig`
(pure) and `src/package_main.zig` (I/O) do.

Checked in the build container (no VM): `dpkg-deb -I` of the deb; `apt-get update` against the
test-key tree with `signed-by=zigbox-test-key.gpg` (InRelease verified, candidate `zigbox 0.3.1`);
the whole two-round flow with a scratch gpg key (header signatures, InRelease, Release.gpg,
repomd signatures), `packages-check` passing on the signed tree and failing on one appended byte.
`rpm`, `createrepo_c` and `dnf` are not in the build container; the earlier slice-6 check (see the
handoff note) ran `rpm -K/-V`, install under `--root` and a `createrepo_c` comparison.

### Known limits (accepted)

- **`primary.xml` differs from `createrepo_c` in one attribute**, `<time file>`, which is a fixed
  epoch here so the output is reproducible. `filelists` and `other` are byte-equal.
- **No `PAYLOADDIGESTALT`** in the rpm header; the file digests are SHA-256 and the payload is
  covered by the header signature.
- **Fedora's rpm 6 needs the key imported** (`rpmkeys --import`) before it accepts a signature,
  the test key included.
- **`packages-check` does not verify OpenPGP signatures** of an owner-signed tree: it checks they
  are present. With `-Dtest-key` it recomputes them and compares bytes. The runbook's
  `gpg --verify` and `rpm -Kv` are the verification.
- **The maintainer string** is a supervisor assumption (`docs/decisions/2026-11-08-package-bounds.md`).
- **VM check:** `.github/workflows/vm.yml` runs the demos m0 to m7 only; see the slice report for
  the status of the `vm/m8-slice6` run.
