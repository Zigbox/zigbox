## Assumptions that were off base

| Assumption | What was true | Cost | What changes |
| --- | --- | --- | --- |
| The 1M fuzz run would find nothing, as in 0.5.2. | `reference` failed at seed 2136361303: a tag of 72 to 128 characters overran a manifest name buffer sized for a digest (71), a crash in `zbx pull` since M10 slice 2 (0.5.1). | One fix session (`d7642ee`), the fuzzers it touched rerun at 1M, about two hours on the critical path. 0.5.1 and 0.5.2 carry the bug; the notes say so. | None to the gate: this is what the 1M run is for. Fixed-size buffers that hold user input get a fuzzer input at the input's documented maximum. |
| One run of a sharded fuzz session survives to the end. | Shard B's first `lazy_resolver` run died near 17:04Z with nothing recorded; the rerun took about 3 h 38 min. | About 3.5 hours on the critical path, the largest single delay of the release. | Shards record each run's last line as it ends, and the slowest fuzzers (`provenance`, `lazy_resolver`) are split into at least 4 shards so a lost one costs under an hour. |
| The Mac signing test in `release.yml` finishes in its time limit. | It was cancelled at about 15 minutes on two heads in a row (runner wait counted against the limit). | Two reruns and the owner's attention. | The job's timeout counts work, not queueing: raise it or split the runner wait off (CI-speed slice). |
| `demo-mac`'s Alpine download is reliable. | It failed once on DNS in the guest. | One rerun. | Cache the Alpine minirootfs in the runner (CI-speed slice). |
| A green release PR means a green `main`. | `demo-m7` on `main` failed with ZBX-E0512 ("registry-1.docker.io sent more than zbx accepts in one answer") pulling a pinned `golang` digest, four hours after the same commit passed it. | One rerun, and `release.yml` skipped its draft until `ci` is green. | The rerun passed, so the oversized answer was transient, not a limit Docker Hub now always exceeds. If ZBX-E0512 recurs on a pinned digest, measure the answer Docker Hub sends against zbx's cap before rerunning, and record the size in an issue. |
