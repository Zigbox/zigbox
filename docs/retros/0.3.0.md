# Retro: 0.3.0 (released 2026-11-04)

Written 2026-11-04 by the supervisor. 0.3.0 predates the release gates in AGENTS.md, so this
also records what those gates would have caught. Items marked (Zigcube) happened in the C2 work
that ran alongside and are kept here because the lesson applies to both repos.

## Assumptions that were off base

| Assumption | What was true | Cost | What changes |
| --- | --- | --- | --- |
| The fuzzers in CI had covered `commit` well enough. | A fresh seed (4368094359180696877, 10,000 iterations) makes the commit digest differ from the oracle's, on main and in 0.3.0. | Unknown until the fix lands: it decides whether a 0.3.1 is needed. | The release gate's extended fuzz run (at least 100 times the default) before every tag. |
| A green `check` means every step passed. (Zigcube) | `check` printed PASS while a `zig build test` step had failed in the same log. | Every Zigcube PASS line since that code is suspect until it is fixed. | A teeth test: a failing sub-step must turn the line into FAIL. |
| Demo checks fail when their command fails. | Two M7 slice 4 checks passed even when their command failed; two failure-mode claims in `docs/demos/m7.md` were wrong. | A review round. | Each demo check is shown to fail once before it is trusted. |
| The supervisor could tag and publish the release. | The git proxy refuses tag pushes and there is no release tool. | The release waited on the owner. | Tagging and publishing are on the owner's list from the start of a release. |
| Data from a peer is safe once its tree is complete locally. | Z4 trusted the manifest digest a peer wrote, so a peer could attach any tree to a well-known digest. | A blocked merge and two fix rounds. | Peer data is checked against a digest the caller already holds; a peer is trusted only against the full 64-hex digest. |
| Tests at toy sizes cover the store. (Zigcube) | Every full-size 1 MiB chunk was flagged corrupt; tests used 40- and 100-byte chunks. Fetch workers also raced on the same chunk. | A review round. | Tests at production sizes and with real concurrency. |
| A test that passed is a test that runs. (Zigcube) | `swarm-smoke` did not compile at a reported head because `check` did not build it. | A wrong pass report. | Every smoke and demo is compiled by `check` (Zigbox's `harness` step already does this for demos). |
| The sim fleet's silence meant the code was clean. (Zigcube) | It ran only plain `sim-cluster` (3 nodes, 100 ops) and filed two issues in its life. | False confidence. | The fleet runs every simulator a gate names, varied shapes, and a teeth canary. |
| std has what the brief names. | Zig 0.17's std has no TLS server and no client certificates, so "mTLS" could not be built. | A mid-slice correction. | Check std before naming a protocol in a brief. |
| New GHCR packages are pullable. | They start private. | demo-c2 waited on the owner. | Check an anonymous pull when the image is pushed. |
| A slice is one implementation and one review. | Slices took two to four review rounds. | Time and spend. | Plan for rounds; reviews say MUST vs SHOULD so a round can end. |
| CI time was the cost of the jobs. | About 30 fuzz jobs and no build cache made CI 23 minutes. | Slow merges. | Zigbox/zigbox#44: one fuzz job, a build cache, affected demos only on PRs. |
