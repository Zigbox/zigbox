# Retro: 0.4.0 (merged 2026-11-11)

Written 2026-11-12 by the supervisor. 0.4.0 shipped M8 (keys, signing, push) for Linux, under the
release gates in AGENTS.md: check PASS, the extended fuzz run, two independent reviews.

## Assumptions that were off base

| Assumption | What was true | Cost | What changes |
| --- | --- | --- | --- |
| 0.4.0 would ship a Mac build, as 0.1.0 to 0.3.1 did. | None of M8's real-Mac checks (slice 9) had run, so no Mac build could be signed for it. | 0.4.0 is Linux only; the tap stays at 0.3.1, and Mac users get M8 only with 0.5.0. | The real-Mac checks and a green `mac` workflow on the release commit are pre-tag gates (`2026-11-11-mac-release-signed-by-owner-for-0.5.0.md`). Each release brief lists every check that has to run on a Mac and who runs it. |
| The release would come with its signed apt and rpm archive. | Signing needed the owner's offline key by hand, and the release workflow could not sign. | 0.4.0 has no archive (owner's call), and zigbox.org's `/apt/` and `/rpm/` stay empty until 0.5.0. | CI signs with a release subkey (#99; `2026-11-11-ci-signs-packages-with-a-subkey.md`). |
| The release workflow could dispatch the zigbox.org deploy. | No token in this repository can write to the site repository. | One amending decision; a release reaches the site on its six-hour schedule. | `2026-11-11-release-workflow-does-not-dispatch-the-site.md`. |
| The gates (demos, fuzzers, two diff reviews) cover what a user runs into. | Writing the user guide on 0.4.0 found six user-visible problems that none of them caught: `zbx stop` on a failed start reports `bug[ZBX-B0001]`; `push --dry-run name@sha256:...` is refused with E0550; `store ls` overcounts hard links; `exec` reads the hostname as `localhost`; E0307's fix text does not fit `zbx build`; `zbx help` does not list `push`. Demos script each milestone's happy path, and reviews read the diff, not the whole CLI. | All six shipped in 0.4.0 and are listed as known problems in `docs/guide/known-limits.md`. | Each is filed as an issue. Before the 0.5.1 public beta tag, the guide's tour runs end to end on Linux and on a Mac, and a `ZBX-B` code reachable from the CLI blocks the tag. |
| The `demo-m8` push stall (E0503 behind pasta) was a test-VM artifact. | Still unproven; #91 is open, and the demo retries once (`2026-11-11-m8-demo-cuts.md`). | A workaround in the demo and a known problem in the guide. | #91 stays open until the stall is reproduced or ruled out outside the VM; if it shows outside the VM, it blocks the next release. |

## What went well

- The release reviews ran on the diff alone, and their follow-ups were filed (#94) rather than
  holding the tag.
- When the owner's real-Mac checks ran (2026-11-11) they passed as predicted, including the known
  ACL gap, so 0.5.0 needs no code change for them.
