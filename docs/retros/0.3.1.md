# Retro: 0.3.1 (merged 2026-11-04)

Written 2026-11-04 by the supervisor. 0.3.1 is the first release cut under the release gates in
AGENTS.md: check PASS, every fuzzer at 200,000 iterations, two independent reviews.

## Assumptions that were off base

| Assumption | What was true | Cost | What changes |
| --- | --- | --- | --- |
| The per-commit fuzz run (2,000 iterations) would catch a wrong fuzzer oracle. | The `pull_report` oracle treated a byte flip that turned `E0515` into another valid error code as a reader bug. 2,000 iterations never hit it; 200,000 did, three times. 0.3.0's fuzzer had the same false positive and shipped. | A fix round and a second 200k run before the tag. | The extended run stays a release gate, not an option. An oracle that asserts an exact value from damaged input must say why the input cannot have produced another valid value. |
| A failing fuzzer means the code under test is wrong. | Here the code was right and the oracle was wrong. | Time spent reading the reader before reading the oracle. | A fuzz failure report says which side is wrong, with the input that shows it, before a fix is written. |
| The release session could tag and publish. | It was briefed not to, and the git proxy refuses tag pushes from the supervisor too, as in 0.3.0. | The tag waits on the owner again. | Already on the owner's list since 0.3.0; from now on the supervisor's release brief names the owner for the tag, the release and the Mac upload. |

## What went well

- The gates ran as written: the extended fuzz run found a real problem (in the test) before the tag,
  and both reviews ran on the diff alone.
- The Z9 fix kept `zbx` behaviour unchanged by making the outside-namespace reading opt-in
  (`Store.owners`), so 0.3.1 is safe to take without Zigcube's adapter line.
