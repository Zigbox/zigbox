# Retro: 0.5.2 (published 2026-11-16)

Written 2026-11-16 by the supervisor. The release reached `main` in #172, merged as `82132cf`. It
shipped M9 (pinned fetches, output pins and excludes), with the S2 lazy-start work that was already
on `main` left dormant. It cleared the release gates in AGENTS.md: check PASS, a 1M-iteration fuzz
run of every fuzzer, and two independent reviews, whose MUSTs were fixed in `4934bb9..7b77cd2`.

## Assumptions that were off base

| Assumption | What was true | Cost | What changes |
| --- | --- | --- | --- |
| `main` held only what the release meant to ship. | S2 slices 1 to 4 had merged to `main` between M9's slices, so a tag from `main` would have shipped a half-built `zbx run --lazy`. | One owner ruling and a "dormant S2" change in the release PR: `--lazy` is refused with E0004, push and export stay on writer 1, and `demo-s2-lazy` builds with `-Dlazy-start`. Every other merge to `main` was held until the tag. #169 then needed a second fix session, because a test it added drove `--lazy` through the CLI. | A milestone that will not ship in the next release merges behind a build option from its first slice, or waits on a branch. A release brief lists what is on `main` and not in the release. |
| A short sha is enough to start a session. | `create_session` with a 7-character sha failed with `ref_not_found`, and the result did not say so. Fuzz shard 3 never started. | About three hours of the fuzz window. | Pass the full 40-character sha, then confirm with `get_session` that the session is running. |
| The self-hosted Mac runner is there when a release needs it. | It went offline twice (jobs queued for hours, and once "lost communication"), and one run failed downloading Zig (`curl 56`). | Most of a day of the release's critical path was spent waiting on the Mac job. Each failure took its one rerun. | The supervisor checks the runner is online before starting a Mac-gated job, and tells the owner at once when a job has been queued for more than 30 minutes. A Zig download that fails is retried in the setup step (follow-up). |
| The first scheduled package refresh would sign with the release subkey. | `ZIGBOX_SIGNING_KEY` was empty in that job's environment. | Its first run failed. Owner's action is open. | The secret's environment scoping is fixed before 0.5.3, and `package-refresh` is run once by hand to prove it. |
| An image built on a Mac is byte-identical to the Linux golden. | The Mac store kept a cached step whose output held `/root/.cache/rosetta`, so `demo-mac` m9.4's digest differed (#168). | Three fix sessions across two days. | `cached_output_holds` drops stale entries rooted outside the build. A cache-format change bumps the step-format version, or says in its decision why it does not. |

## What went well

- Both reviews ran on the diff alone. Review A caught a re-export (`runtime/exec.zig`) that let `exec.start` bypass the trust gate.
- The dormant-S2 change kept writer-1 output byte-identical to v0.5.1, checked against E0555's golden.
- The 1M-iteration fuzz run found nothing.
